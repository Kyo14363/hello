6. **來源：** [論壇 172568](https://forum.cursor.com/t/userhome-on-windows-isnt-expanded-in-mcp-config-the-same-as-on-macos-linux/172568)（mohitjain 12:27Z）＋ [論壇 172829](https://forum.cursor.com/t/mcp-elicitation-allow-deny-is-often-not-visible-unless-mcp-tool-row-is-expanded/172829)（kevinn 9/24 00:42Z）＋ [論壇 172616](https://forum.cursor.com/t/alerting-for-missing-authentication-in-cursor-automations/172616)（kevinn 23:48Z）＋ [論壇 172838](https://forum.cursor.com/t/in-multitask-chat-questions-get-lost/172838)（kevinn 9/24 00:29Z）  
   **主張：** Windows `mcp.json` 的 `${userHome}` 會變成 `/c:/Users/...`，stdio 起不來；`~/` 只在有 workspace 時展開，Shared MCP process（無資料夾）會原樣 spawn 失敗。跨平台穩健寫法是 `${env:HOME}${env:USERPROFILE}/...`。MCP form elicitation 的 Allow／Deny 常被收進收合的 tool 列，不展開就像卡住、可撞 ~60s timeout。Automations 的「Needs authentication」**沒有過期告警**，只在打開該 automation 的 Tools 看得到。Multitask／subagent 的 question card：新 turn 一進同一則 chat（你打字或背景 agent 回報），開著的卡連已選答案一起丟。  
   **為什麼值得記：** 這四則都是可複測的「看起來像 agent 死了」。雲端／排程演示若 MCP 沒回，先展開 tool 列、看 Tools 是否 Needs authentication，再怪模型。
