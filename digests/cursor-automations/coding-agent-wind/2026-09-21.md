3. **來源：** [forum/172143](https://forum.cursor.com/t/cloud-agents-marketplace-plugins-hosted-on-azure-devops-dev-azure-com-are-silently-dropped-github-hosted-plugins-install-fine/172143/5)（Colin，9/19 15:45Z；週五 digest 之後）

   **為什麼值得記：** 企業 ADO marketplace ≠ Cloud Agent 可用。失敗不進 run events，看起來像「MCP／plugin 沒接上」而不是明確拒絕。

4. **來源：** [forum/169638](https://forum.cursor.com/t/cloud-agent-logs-claude-4-5-sonnet-when-picker-is-grok-4-6-and-claude-is-not-enabled/169638/21)（deanrie，9/20 14:04Z）

5. **來源：** [forum/172373](https://forum.cursor.com/t/linux-sandbox-step-4-7-mount-denies-enoent-on-nested-vscode-under-a-cursorignore-d-parent/172373/5)（deanrie，9/20 09:00Z）  
   **主張：** Linux sandbox 先依 `.cursorignore` 藏資料夾，再保護它掃到的每個 `.vscode`。若 `.vscode` 在已被藏的父目錄底下，第二步找不到路徑就 crash，而不是 skip。Workaround：該 workspace 關掉 shell sandbox（Run Everything／Allowlist without sandbox），或把 workspace root 移出被 ignore 的樹。  
   **為什麼值得記：** 可重現的 IDE agent 限制，不是「模型笨」。忽略私有目錄 + 巢狀 `.vscode` 會讓 agent 直接起不來。
