2. **來源：** [forum/172035](https://forum.cursor.com/t/nested-subagent-gets-a-broken-tool-schema-for-launching-further-subagents-no-working-task-tool-contradicts-docs/172035/7)（kevinn，2026-09-18 00:16Z）；對照官方文件 [Subagents](https://cursor.com/docs/agent/subagents)  
   **主張：** 文件寫「自 2.5 起，直接子 agent 可以再長出子 agent」。員工確認：**IDE 與 CLI 可以巢狀啟動；SDK（本機與 cloud runtime）不行**——直接子 agent 拿不到 `task` 工具，動態工具清單也不會列出它，所以呼叫失敗是預期。沒有 `local.allowNestedTaskTool` 這類開關。暫用做法：由頂層 agent 扇出，編排提示寫在主 agent 裡。  
   **為什麼值得記：** 官方文案把 editor／CLI／Cloud Agents 寫成同一套；今天第一次有員工承認 SDK 路徑與文件不一致。

3. **來源：** [forum/171877](https://forum.cursor.com/t/grok-bot-custom-mcp-oauth-fails-before-sign-in-redirect-uri-not-allowed/171877/8)（deanrie，2026-09-17 18:32Z）  
   **主張：** 昨天建議的 Cloudflare Access service token + header **不適用 Grok Bot**。Bot 的 connector 只走 OAuth，token 存在後端；UI 沒有 owner-only secrets、也沒有安全輸入任意 header 的地方。`AddMcpServer.headers` 只在 API 層存在。要解仍是 Cursor 自己在 DCR 時拿掉 `cursor://`，只送 https + localhost；尚無時程。  
   **為什麼值得記：** 把「Cloud MCP 可以貼 header」與「Grok Bot 只能 OAuth」拆開；https-only 供應商在 Bot 上目前沒有可驗證的繞路。

4. **來源：** [forum/171997](https://forum.cursor.com/t/project-feature-experience-sucks/171997/7)（deanrie，2026-09-17 17:14Z）  
   **主張：** Project 主對話是 coordinator，**自己不改碼**，只派雲端 worker 再追進度。這次 worker「Investigate gap-check duplication」啟動後數分鐘沒開工，coordinator 就一直改 Project 內部的 `events.json`／`index.json`／`setup-logs.txt`／`notes.md`（不動你的 repo），token 燒了卻沒產出。員工說不該發生。小改一檔，先用一般 Cloud Agent 或本機聊天，少一層 coordinator。  
   **為什麼值得記：** 官方 Projects 文案仍寫「delegates tasks to thousands of subagents」；實作上單檔小事會被編排層卡住，而且內部日誌看起來像在改檔。

5. **來源：** [forum/172058](https://forum.cursor.com/t/how-does-cursor-router-handle-context-limits/172058/5)（kevinn，2026-09-17 18:17Z）；同窗 [forum/172008](https://forum.cursor.com/t/pro-models-stuck-at-1m-context-size-cant-switch-back-to-272k/172008/8)（kevinn，22:53Z）  
   **主張：** Router **永遠用各模型標準窗**（現池約 256K–300K），不會因任務或對話長度改選 1M；要 1M 只能手動選支援的模型，長對話靠摘要。另一頭：GPT-5.6 一旦開過 1M，選回 272k **不會清掉**，實際請求仍走 1M，產品內沒有重設鈕。單價在 272k 以內相同，超過 272k 才加價。  
   **為什麼值得記：** 「Router 會依任務自動開長窗」與「選回 272k 就變短」兩種直覺都不成立。

6. **來源：** [forum/172038](https://forum.cursor.com/t/custom-subagent-ignores-its-card-and-claims-it-is-the-parent-agent-production-unusable/172038/6)（kevinn，2026-09-17 23:59Z）  
   **主張：** `.cursor/agents` 卡片會加進子 agent 指示，**不會取代**底層 system prompt；子 agent 也會讀到父層的 `.cursor/rules`／`AGENTS.md`，所以子 agent 自稱「我是父 agent」往往是規則衝突，不是卡片被丟掉。9/16 更新後自訂子 agent 能再長子 agent 的問題**仍在追**（昨天 171797 的伺服器端撤回並未關這條）。  
   **為什麼值得記：** 自訂 agent 卡不是隔離身份；「不要再啟動子 agent」仍要寫進卡片本身。
