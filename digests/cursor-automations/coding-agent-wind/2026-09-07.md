# coding-agent-wind｜2026-09-07

今天沒有夠硬的更新。官方 changelog 與 [@cursor_ai](https://x.com/cursor_ai) 都停在 9/2 的 Self-hosted Machines；近 24 小時能核對的是落地崩潰、Cloud Agents 公開串流比網頁慢，以及 MCP「每輪灌進全量 schema」被作者自己改口。

1. **最接近一則（9/2 官方，非今日）**  
   來源：[Changelog · Self-hosted machines](https://cursor.com/changelog/self-hosted-machines)、[產品文](https://cursor.com/blog/self-hosted-machines)、[官方貼文](https://x.com/cursor_ai/status/2095257412781396114)  
   主張：Cloud Agent 的工具執行可放到自家機器或既有 sandbox（AWS Lambda、Cloudflare、Vercel、E2B 等）；推論與規劃仍在 Cursor。Linux／Mac worker 宣稱支援 computer use。文中寫內部超過 60% 合併 PR 由 cloud agents 產出。  
   為什麼值得記：這是目前最近的可驗證產品面更新。9/6 論壇已出現 macOS `--computer-use` 啟動即崩，代表「能跑在你機器上」與「desktop 真的能點」還不是同一件事。

2. **macOS self-hosted computer-use：兩條路都死**  
   來源：[論壇 bug（9/5 開、9/6 複現）](https://forum.cursor.com/t/macos-self-hosted-worker-agent-worker-computer-use-start-crashes-at-startup/170703)  
   主張：`agent worker --computer-use start` 在 signed SEA（`cursor-agent-worker-sea`）因 `createRequire` 被關掉而崩潰；關掉簽名改走 unsigned node 後，本地 RPC 又不信任非 Anysphere team 的行程。CLI 標成 `2026.09.02-c22c1a3`。沒加 `--computer-use` 則 worker 可跑。  
   為什麼值得記：可複現、有錯誤字串與 CLI 版本，是對 9/2 computer-use 宣布最硬的限制，不是氣氛文。

3. **Cloud Agents 公開 API／SDK 比網頁 UI 慢 20–40 秒**  
   來源：[論壇 2026-09-07 00:10 UTC](https://forum.cursor.com/t/cloud-agents-api-sdk-stream-delivers-intermediate-messages-steps-20-40s-later-than-cursor-com-agents-ui-on-the-same-run/170833)  
   主張：同一 `bc-…` run 在 [cursor.com/agents](https://cursor.com/agents) 約 2–4 秒出泡泡；`@cursor/sdk` 的 `onStep`／`onDelta` 與公開 run stream 常在 Get A Run 已 `FINISHED` 才吐同一段字。  
   為什麼值得記：這是「把 Cloud Agent 當產品後端」的可觀察差距，問題在串流同步，不是模型會不會寫程式。

4. **MCP 目錄成本可量、但「Cursor 每輪都灌全量」被撤回**  
   來源：[論壇串（9/6 作者更正）](https://forum.cursor.com/t/mcp-context-cost-see-what-the-mcp-servers-in-your-cursor-config-cost-in-context-tokens-before-you-type-anything/170692)、[GitHub 工具](https://github.com/athakur3/mcp-context-cost)、[官方 Dynamic context discovery](https://cursor.com/blog/dynamic-context-discovery)  
   主張：`npx -y mcp-context-cost audit` 量的是各伺服器 `tools/list`；作者列 GitHub 官方 MCP 54,622 tokens、postgres 32 tokens。9/6 他自己承認「每輪都帶全量」是文件空缺推論，不是 Cursor 請求實測。官方寫法是只靜態給工具名、需要時再載入，A/B 稱 MCP 有呼叫的 run 少 46.9% tokens。  
   為什麼值得記：同時示範可驗證量測（目錄很大）與把目錄成本直接當成 Cursor 帳單的誇大。

5. **X：有人六個月後回來誇 Cloud Agent UX；「85% 程式由 bot 寫」仍無演示**  
   來源：[nick_kango 9/6](https://x.com/nick_kango/status/2096476628687941690)（129 likes）、[thomasgauvin 談 harness++](https://x.com/thomasgauvin/status/2096642977498018110)、[無法核對的 85% 剪輯](https://x.com/0xMovez/status/2096612265592021396)  
   主張：回歸使用者點名 cloud agents、多工、in-app browser 與 agent 熱重載。另一則把 Cursor／Claude Code／Codex 叫成「harness++」（有 desktop／mobile／cloud，不再只是 CLI）。病毒剪輯稱 85% 程式、10–20 個 GrokBot，無 repo、無錄影、無官方對帳。近 24 小時 X 上 Cursor+agent／MCP 相關貼文約 322 則。  
   為什麼值得記：訊號在「平台化」敘事，不是新品；高互動剪輯先當誇大，等可重跑的 repo 或官方數字。
