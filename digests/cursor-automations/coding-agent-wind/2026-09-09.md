2. **Cloud Agents 公開 stream：API 路徑會先載完整歷史，長對話一次噴出**  
   來源：[論壇 170833](https://forum.cursor.com/t/cloud-agents-api-sdk-stream-delivers-intermediate-messages-steps-20-40s-later-than-cursor-com-agents-ui-on-the-same-run/170833)（員工 Colin 9/8 10:38 UTC；回報者 13:14 複現）  
   主張：連上後伺服器先載完整對話歷史才轉發 live 事件。短對話聲稱 1–2 秒；數百輪要 30 秒以上，期間文字一次噴出。網頁 UI 會告訴伺服器「哪些歷史已有」所以跳過這段。回報者同提示複測：新 agent（1 輪）中間句 11.2 秒（run 還在 RUNNING，仍遠慢於 UI）；長歷史 agent 中間句 83.8 秒、FINISHED 後約 60 秒才一次噴出。  
   為什麼值得記：昨天是啟動競態；今天員工把「連上了仍晚」釘成 API 路徑的歷史載入。把 Cloud Agent 當產品後端時，長壽命 `bc-` 的公開 stream 仍對不齊 UI。

3. **Windows 3.19.13：員工說不是 Ultra 限速，是本機 Grep／Read／edit 從 1 秒變成 20 秒到數分鐘**  
   來源：[論壇 171047](https://forum.cursor.com/t/composer-and-grok-slow-down-and-stalling/171047)（Colin 9/8 19:16 UTC；回報者 19:49 對 Grep）  
   主張：Grok 4.6／Composer 2.5 在 agent 與 multitask 常跑不到 6 步就停。員工看過帳號：模型本身數秒內回，卡在本機檔案搜尋、讀取、編輯；對上 3.19.13（commit `dd066f3`）。Ultra 用到 50–60% 變慢的說法被否決。  
   為什麼值得記：可核對的 IDE agent 限制在本機工具步，不在模型選擇器。同一版也有 [Remote SSH agent 卡死](https://forum.cursor.com/t/remote-ssh-agent-hangs-second-extension-host-spawns-with-vscode-lock-eexist-despite-cursor-agent-exec-ready-on-exthost1/171095)（第二個 extension host 搶 `vscode.lock`），尚無員工回。

4. **Cloud Agent 上的已驗證 Context7 MCP：IDE OAuth 過了，雲端 API key／repo `mcp.json` 過不了**  
   來源：[論壇 171106](https://forum.cursor.com/t/how-do-you-use-authenticated-context7-mcp-in-cloud-agents/171106)（9/8 23:10 UTC）；對照 [Cloud Agent MCP 文件](https://cursor.com/docs/cloud-agent/capabilities#mcp-tools)  
   主張：本機用 OAuth 可讀私有 docs。雲端試過：Customize 裝 Context7 plugin 沒有 API key 欄；自訂 HTTP MCP 在選單只顯示本機連線；repo 裡的 `.cursor/mcp.json`（再 symlink 到環境）被雲端 agent 報 namespace 未正確設定。文件寫的是 [cursor.com/agents](https://cursor.com/agents) 的 MCP 下拉或 Dashboard → Integrations & MCP，HTTP 的 `headers` 存在後端、不進 VM。  
   為什麼值得記：這是今日最清楚的「IDE MCP ≠ Cloud Agent MCP」實作缺口；同一人還 bump [Cloud Agent 不跟 symlink skills](https://forum.cursor.com/t/symlink-support-for-skills-missing-in-cursor-cloud-agent/153603)。
