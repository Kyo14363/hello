2. **員工確認：Team Rules 不能藏、不能加密；專有邏輯請放到自己託管的 MCP／API**  
   來源：[論壇 170776](https://forum.cursor.com/t/hide-and-encrypt-rules/170776)（Colin 9/13 10:33 UTC）  
   主張：今天沒有「對成員隱藏或加密 Team Rules」的做法。Rules 是 agent 替每個成員讀的指示，Settings 與 dashboard 都看得到；模型收到的內容也能被使用者問出來（例如叫 agent 複述）。這不是 Cursor 獨有，任何 AI coding tool 都無法保證「能用但不能讀」的 prompt 保護。真要藏 know-how：不要寫進 prompt，放到自己託管的 MCP 或內部 API，讓 agent 只看到工具 I/O（工具輸出對使用者也可能可見）；Team Rules 只寫何時呼叫那些工具。  
   為什麼值得記：這是窗口內最硬的產品限制。Projects／Cloud Agents 正在賣「共享上下文長過好幾個月」——共享的那份檔預設不是機密容器。

3. **週末補答（上期未解）：Cloud Agents 的認證 MCP 只認 dashboard，不讀 repo `mcp.json`**  
   來源：[論壇 171106](https://forum.cursor.com/t/how-do-you-use-authenticated-context7-mcp-in-cloud-agents/171106)（deanrie 9/12 09:25 UTC；窗口外約 15 小時，因週一～五排程週末沒出報）  
   主張：雲端 agent **不讀** `~/.cursor/mcp.json` 或 repo 裡的 `.cursor/mcp.json`，symlink 無效。雲端只吃帳號在 [cursor.com/agents](https://cursor.com/agents) 的 MCP 清單。Marketplace 的 Context7 外掛是匿名版、沒有 API key 欄。做法：Agents 頁 `+` → MCP Servers → 先刪掉同名 Context7 → Custom MCP（HTTP，`https://mcp.context7.com/mcp`）→ Headers 直接貼 `CONTEXT7_API_KEY`（或 `Authorization: Bearer …`）。**`${env:...}` 在 Cloud Agent MCP 設定不會展開**；值靜態加密。舊 agent 不會自動帶上，要開新的。OAuth 則改 URL `https://mcp.context7.com/mcp/oauth` 再 Authorize。  
   為什麼值得記：把「Cloud MCP ≠ 桌面 mcp.json」從記憶裡的推測寫成員工步驟。也解釋為什麼 My Machines／雲端常出現「本機有、雲端沒有」的 MCP。
