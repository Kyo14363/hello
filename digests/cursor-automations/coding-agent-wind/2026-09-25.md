 **主張：** Rollouts 現在有獨立操作頁。監控範圍是 Origin、GitHub、GitLab.com、Bitbucket Cloud，最多 200 個 repo。部署當下查一次，再在 20 分鐘／1 小時／1 天／3 天複查。沒接遙測（docs 寫 Data sources 是 **MCP 連線**）就一直 Pending、偵測不了回歸。回歸時開 issue、通知作者，頁上選 Fix 才開 cloud agent，或 Close 附原因。**docs 寫明不會自己 merge、revert、rollback**——這比 changelog「設定後可開 revert PR」更窄。改計畫要 @ 留言裡的 handle，且要有 write access。預設用自然語言略過純文件／格式／測試變更。Slack 通知要團隊先把 Rollouts 加進 Slack；Privacy Mode 沒有 Slack。 
 **為什麼值得記：** 昨天官推「deployments are verified, so regressions are caught before users see them」被這頁拆開：沒遙測＝Pending；inconclusive 仍在；人按 Fix 才有 cloud agent。任何「一鍵回滾」演示，先對這句：官方操作頁現在連 revert PR 都不承諾。

3. **來源：** [論壇 172889](https://forum.cursor.com/t/auto-usage-suddenly-reaching-100/172889)（Colin 17:53Z） 
 **主張：** Auto 用量條從 ~40% 跳到 100% **不是記錯帳**。方案有 Cursor Models 池（Auto 先吃這池）和較小的 Other Models 池；Cursor Models 用完後 Auto 繼續跑、改記 Other Models，百分比因此跳。Auto 現在依**實際路由到的模型**計價，不是扁平 Auto 價；長 agent session 比以前更快吃完內含額度。員工建議：一任務則 chat、少用 Fast、簡單工作直接點 Composer 2.5。後續有人用 Ultra 對不上公開牌價，窗口內還沒員工回。 
 **為什麼值得記：** 這把「Auto 比較省」從行銷句改成可測的雙池＋路由價。長跑 agent 演示若只截 Usage 條，先看是 Cursor Models 滿了溢到 Other Models，還是真的被加價。

4. **來源：** [論壇 172935](https://forum.cursor.com/t/cloud-agent-didnt-get-env-setup-as-before/172935)（Colin 19:28、22:10Z）＋ [論壇 172939](https://forum.cursor.com/t/project-workspaceopen-hook-never-runs-the-event-fires-during-a-hooks-config-reload-before-project-hooks-are-registered/172939)（Colin 22:09Z） 
 **主張：** Cloud Agents API 傳 `repos[]` 會重用「同一組 repo」的既有 environment；**順序不一致就 checkout 失敗**（`Couldn't check out the repository`）。重試同一則 agent 會沿用舊設定，必須開新的。更穩是具名 `env: { type: "cloud", name }`。刪掉可見 environment 後，API 仍可能掛上**未完成、列表裡看不到、沒有 details 頁**的殘留 env（名稱帶 `+1`）。另：專案 `.cursor/hooks.json` 的 `workspaceOpen` 在 hooks 重載期間就派發，專案 hook 還沒註冊，**沒有可靠 workaround**；團隊 marketplace／Customize 能裝插件，但不再是 repo-scoped。這讓「用 hook 自動載入 workspace MCP／plugin」的文件路徑目前是斷的。 
 **為什麼值得記：** 多 repo API 演示失敗，先對 repo 順序和隱藏 env，不要當 Dockerfile／模型問題。repo 級 MCP 自動掛載若靠 `workspaceOpen`，今天員工已複現為啟動競態。

 **主張：** Security Agents（含 Vulnerability Scanner、Security Reviewer）和 Automations **尚未支援 Azure DevOps**；設了也不會開跑。官方 ADO 頁同樣把 Automations／Security Agents 列在不支援，只給 Cloud Agents 與 Bugbot（無 autofix）。Rollouts 操作頁的 SCM 名單也沒有 ADO。單 repo 的 Scanner 週期／cron 現在不必再選 branch，排程走 default branch。 
 **為什麼值得記：** 9/23 把 Security Reviewer 和 Rollouts 綁在 Automations 上架，但 ADO 團隊連觸發都沒有。這和 9/19 Colin 說 Cloud Agents 會靜默跳過 ADO-hosted marketplace plugin 是同一條縫：GitHub／Origin 演示不能外推到 ADO。

 **主張：** GPT-5.6 選過 1M 後 picker 切回 272k 仍走 1M（圖表是真窗口）的修補已進 **即將到來的 3.22**；更新後還要再選一次 1M 再切回才清記憶。佇列訊息顯示已送、agent 沒啟動的修補標 **3.23**。Remote SSH 在遠端沒出站網路時，最新版可自動改走本機轉送；自己加的 `remote.extensionKind` override 反而會製造 agent-host-bridge timeout。Grok Bot「Always allow」存的是**文字指令、不是 per-tool 權限**，同類動作仍可能再跳卡；手動寫寬一點的 Auto-review Allow 比較穩，規則滿了會踢最舊的，衝突時 Ask first 優先。同 workspace 新 worker 不再在舊 worker 還活著時再起，重複 MCP 進程不該再堆；`pgrep -cf 'cursor-agent.*worker start'` 應約每 workspace 一個。iOS 把同一台 Mac 上的多個 self-hosted worker 收成一列，要靠 runtime＋repo picker 對到人；同一 repo 兩個 worker 或非 git 資料夾對不上。
