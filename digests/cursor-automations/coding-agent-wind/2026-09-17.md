4. **來源：** [forum/171877](https://forum.cursor.com/t/grok-bot-custom-mcp-oauth-fails-before-sign-in-redirect-uri-not-allowed/171877)（deanrie，2026-09-16 14:19Z）  
   **主張：** Dynamic Client Registration **桌面與 Cloud Agents 送同一組** `redirect_uris`：`cursor://anysphere.cursor-mcp/oauth/callback`、`https://www.cursor.com/agents/mcp/oauth/callback`、`http://localhost:8787/callback`。Cloudflare Managed OAuth 只收 `https`，整包被 `cursor://` 擋下。目標是註冊時只送 https + localhost，尚無時程。自建伺服器可暫改 Cloudflare Access service token + header，不要走 OAuth。  
   **為什麼值得記：** 比「Cloud 仍回 `cursor://`」更清楚：HTTPS callback **已經列在陣列裡**，但 `cursor://` 仍會讓只准 https 的供應商整次註冊失敗。

5. **來源：** [forum/171919](https://forum.cursor.com/t/acp-pycharm-connection-blips-fail-instantly-no-auto-retry/171919)（kevinn，2026-09-16 20:46Z）  
   **主張：** 互動／headless CLI 對短暫斷線或 DNS 的自動重試，**尚未接到 ACP**；PyCharm 第一下失敗就直接丟給使用者。`cli-config.json` 的 `useHttp1ForAgent` 只改傳輸，不開重試。暫用重送；長任務被切斷可用 `cursor-agent --resume` 從終端機接回（那條路有重試）。  
   **為什麼值得記：** 這是 IDE agent（JetBrains ACP）與 Cursor CLI 行為不一致的可驗證限制，不是設定錯。

6. **來源：** [forum/171791](https://forum.cursor.com/t/grok-bot-github-issue-assigned-routine-never-fires-5-attempts-recreated-routine-app-has-repo-access/171791)（deanrie，2026-09-16 05:59Z）
